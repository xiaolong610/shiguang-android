# 四类搜索与加载优化（0.9.1）

用户反馈全部规则启用后，影视、动画、漫画、小说都慢。代码检查定位到公共流程的等待、请求取消和界面计算问题。没有读取用户手机的网络记录，因此不能断言每个网站具体慢在哪里。

## 原因与修改

| 原流程 | 影响 | 当前处理 |
| --- | --- | --- |
| 仅3个搜索并发，等待所有源后一次返回 | 快站点被慢站点拖住，启用越多等待越久 | 普通6并发、动态网页独立1并发，完成一个源即可更新已有结果 |
| 页面加载时用转圈替换作品列表 | 已有结果也不可见 | 保留网格，用紧凑进度条显示后台搜索，可停止 |
| 阻塞网络调用没有联动协程取消 | 换关键词或离开页面后旧请求仍占位置 | 异步请求与取消绑定，响应体读取期间同样可取消 |
| 自动一次搜索全部启用规则 | 不可用或动态站点扩大首轮耗时 | 历史快源优先；默认6／8／12个，继续每批24个，可主动搜索所有剩余源 |
| 缺少作品索引、相同详情反复请求 | 短关键词依赖远端，重复开页也联网 | 本地保存已见作品，详情短缓存；追更／重试强制刷新 |
| 网格逐卡扫描聚合结果与进度 | 结果多时界面计算接近平方增长 | 预先建立作品分组与进度映射 |
| 部分页面解析在界面线程 | 列表／目录较大时卡顿 | 搜索、目录与正文解析放到后台 |
| 阅读预取任务无人等待后仍存活 | 占用两条正文加载位置 | 最后一个使用者离开后短暂等待接续，随后取消旧请求 |

普通源每次搜索最多等待7秒，动态源12秒；普通批次总预算20秒。主动“搜索全部剩余来源”会持续分批返回且可停止，耗时取决于来源数量。连续失败两次的源在15分钟内排后，未被永久禁用；修改规则后旧性能记录失效。

## 少字与模糊匹配的范围

本地索引保存最近七天最多8000条已见作品元数据，来源需仍启用、规则指纹一致。收藏、历史和本地小说也参与当前分类的本地匹配。只索引返回过的作品，不能凭空知道网站未返回的标题。

匹配支持全半角、大小写、空格和标点归一化；完整／前缀／包含匹配优先，其次分词、有限跨度漏字和有限编辑距离。单字仅做真实字符包含，避免把大量无关标题当作错字匹配。建议词来自实际已知作品，没有自动编造别名。

本地结果先显示，网站使用输入关键词正常搜索。首轮无结果且至少三个字符时，最多在两个已成功响应的普通源上尝试两次较短关键词，随后按原输入筛选。未实现拼音、繁简别名或全网语义搜索。冷启动短词能否找到未见作品仍受网站搜索能力限制；可用“继续查找”扩大来源范围。

## 验证方法

`SearchPerformance091Test` 用30个受控加载器，前5个各延迟400毫秒、其余25个各延迟20毫秒，对比旧3并发／等齐展示与新6并发／渐进展示。全部30条最终结果必须保留，首条结果必须先于旧流程完成。该测试说明等待方式改变带来的收益，不包含DNS、TLS、验证码、手机网络或网站限流，不能用于承诺真实网站速度倍数。

Android测试用本地HTTP服务器分别模拟四类快源和慢源，验证慢源未完成时快源作品可见；另验证少字索引立即显示、停止后保留结果、首轮源数受限、扩大至全部后不重复已完成请求。数据库测试验证升级、缓存期限、禁用与改规则过滤、失败后恢复。播放／阅读／订阅的原有27项用例继续回归。

真实网页仍可能失效或反爬。规则包的263条表示可导入的目录数量，本次未重新认证263个真实站点。
