# 拾光 Android

一个独立实现的多源影视、动画、漫画和小说客户端。当前版本 **0.9.1 搜索优化版**，最低支持 Android 8.0（API 26）。

<img src="docs/branding/shiguang-fairy-master.png" width="112" alt="拾光精灵图标">

**[下载安卓安装包](https://github.com/xiaolong610/shiguang-android/releases/latest)** · [查看页面截图](docs/screenshots/README.md) · [源码构建与验证](docs/BUILD.md) · [第三方说明](THIRD_PARTY_NOTICES.md)

在 Releases 下载 `shiguang-0.9.1.apk`，传到安卓手机安装即可。已安装旧版可直接覆盖，无需卸载。若仓库为私有，手机需登录有访问权限的 GitHub 账号才能下载附件。

规则导入：在 Releases 下载 `rules-tested-11.json`（推荐）或 `rules-all-263.json`（完整目录），在 App 中选择“内容源 → ＋ → 文件 → 从文件选择”。完整目录不代表所有站点目前都能使用。规则文件仍为 0.6.0 分类规则版本，兼容 App 0.9.1。

## 0.9.1：四类搜索与加载优化

- 搜索结果陆续显示，加载期间可点击已找到的作品；支持停止、继续查找和搜索全部剩余来源，修改关键词会取消旧网络请求。
- 按同类启用源的历史响应排序，普通请求最多并发6个，动态网页单独排队。默认最新列表先查6个源、单字搜索8个、其他关键词12个；“继续查找”每次增加最多24个。剩余范围有明确数量提示，源的启用状态不变。
- 本地已见作品索引支持单字、片段、分词、漏字和有限错字匹配，完整匹配优先，提供已知书名建议。首次未见作品仍依赖网站返回；首轮无结果时最多增加两次较短关键词请求，不向所有网站重复广播。
- 搜索与详情使用独立请求队列，解析移到后台；详情有两分钟短缓存，追更和手动重试强制刷新。离开阅读页面后取消无人使用的旧请求，释放加载位置。
- 数据库增量升级，原规则包、收藏、阅读进度和追更记录继续使用。见 [优化与验证说明](docs/SEARCH_PERFORMANCE.md) 和 [版本说明](release/0.9.1-搜索与加载优化说明.md)。

## 0.9.0：收藏追更、聚合换源与阅读播放体验

- 书架显示新增与未读章节／集数，支持“有更新”筛选、手动刷新、约每12小时自动检查及关闭自动追更。首次检查建立目录基线，失败保留旧结果。网站规则订阅与作品追更独立运行。
- 发现页按分类与规范作品名合并不同来源，保留季数、年份和版本差异；同站存在多个同名条目时保留独立结果。详情及播放器设置可搜索其他启用来源，核对版本并确认章节后切换，原源进度保留。
- 视频同集换源可沿用时间位置；小说／漫画换源从所选章节开头阅读。章节匹配失败时手选，不直接使用另一网站的章节序号。
- 画面中央双击播放／暂停，长按临时至少2倍速，松手或切后台恢复原倍速。全屏返回先回竖屏窗口，再返回离开播放器，播放与暂停状态保留。
- 小说／漫画正文使用最多24章、12MiB的会话缓存；非计费网络预取下一章／话，漫画准备后续三张图片，加载失败可单张重试。正文缓存约30分钟到期，不等同于离线下载管理。
- 沿用拾光精灵图标与此前签名，数据库增量升级保留原收藏、规则与阅读进度。完整行为见 [版本说明](release/0.9.0-追更换源与流畅体验说明.md)。

## 目前可用

- 影视、动画、漫画、小说分类与聚合搜索；普通源最多并发6个、动态网页单独排队，结果渐进显示，单个源失败独立展示。
- MacCMS JSON视频接口：搜索、详情、多线路、选集。
- 视频直链：主页右上角“＋”→打开视频链接，支持HTTP(S)的MP4/M3U8等地址。
- Media3原生播放器：系统播放控制、横竖屏切换、倍速、进度保存、同线路自动下一集、磁盘缓存（上限256MiB）。
- 小说独立阅读器：目录、书签、字体与行距、四种配色、亮度、沉浸阅读、位置恢复；支持本地TXT导入与系统离线中文听书。
- 漫画阅读：上下条漫、常规翻页、日漫右翻、章节切换与阅读进度。
- 收藏、最近看过；数据保存在本机SQLite数据库。
- 从文件、粘贴JSON或链接导入内容源；导出、测试、启停和移除。
- 兼容Ficket视频API源列表中的`name`/`api`结构。并不代表兼容Ficket所有源类型。
- 自有HTML规则：CSS选择器解析搜索、详情、章节、正文和图片。

内置内容明确标记为示例：原创离线小说、漫画和十二秒光影视频。没有预置第三方影视聚合站或私有服务凭据。

## 安装和使用

1. 从 [Releases](https://github.com/xiaolong610/shiguang-android/releases/latest) 下载 `shiguang-0.9.1.apk`，传到安卓手机并覆盖安装。它使用与前版相同的本地调试签名，适合个人安装验证。
2. 首次打开可进入小说/漫画，测试离线阅读、收藏和续读。
3. 主页“＋”→打开视频链接，可粘贴自己的视频直链；“＋”也可导入本地小说。
4. 内容源右上角“＋”，选择文件、订阅链接或粘贴规则；分类下拉可筛选影视、动画、漫画和小说。
5. 返回发现，切换对应分类，输入关键词并点击搜索箭头。空关键词对于MacCMS接口表示请求最新列表；网页源如何处理空关键词由网站本身决定。

API源最简格式：

```json
{"name":"我的视频接口","engine":"maccms","kind":"video","url":"https://example.com/api.php/provide/vod/"}
```

也可以直接粘贴API地址。模板目录中的`example.com`只是占位地址，需要替换后才能访问实际内容。

网页规则见`examples/网页源模板.json`。必填项：`searchUrl`（可含`{query}`）、`list`、`title`、`chapters`，以及小说的`content`、漫画的`images`或视频的`media`。可配置链接/图片属性、简介选择器、章节倒序和请求头。

## 0.6.0：100MiB小说与Ficket规则适配

- 本地导入扩展到TXT/TEXT、EPUB、FB2、HTML/HTM/XHTML、Markdown、RTF、DOCX、PDF文字层、未加密MOBI/AZW/AZW3/PRC，以及只含一部书的ZIP；单个输入文件上限100MiB（104857600字节）。
- 正文按章/分段存储为独立文件，翻章只读当前章，保留0.4/0.5旧版导入书籍。大文件不再把整本正文塞进一个JSON后反复解析。
- EPUB按spine顺序读取，提取目录标签与书名；保留FB2目录，DOCX/PDF等提取现有文字供阅读与听书。PDF扫描图片不含可读文字时会提示需OCR；DRM加密书、旧二进制DOC、CHM/UMD和图片OCR不在本次支持范围。
- MOBI/KF8通过独立动态库libmobi解析，构建时禁用加密处理，拒绝DRM文件。四种Android ABI原生库随APK提供；源码包带完整libmobi源代码、JNI和LGPL/GPL许可，允许修改重建。
- Ficket影视、漫画、小说网页及API/混合规则新增适配：POST搜索、字符编码、独立目录页/分页、声明式字段及部分经审阅脚本的原生等价处理；动态页面在无Android系统桥的WebView中提取。
- 规则导入与订阅统一上限500条。完整规则包包含安装资源、Steam工坊订阅、旧规则备份以及官方Kazumi当前/历史规则，按类别及检测结果分包；导入格式通过不等于站点当前可播放。
- 具体交付与检测范围见release/0.6.0-使用与验证说明.md。

## 0.3.0 新增：订阅与在线播放

- 播放器由独立MediaSessionService管理，离开播放页、锁屏仍可继续；通知栏和主界面播放条可回到播放器。
- 支持系统画中画及自动小窗；横屏隐藏设置区，视频占满可用区域。
- 链接可保存为订阅：自动检查、立即刷新、暂停、取消和恢复上一版。规则更新保留启停选择、本地修改及手动删除记录；上游移除的源保留并停用。新出现的广告标记默认停用。
- 接入Kazumi传统XPath及基础API规则：GET/POST、请求头、相对地址、多线路、简单JSONPath、嵌套/分隔剧集与页面模板。不是所有Kazumi规则语法的完整复刻；特殊模式会提示不兼容。
- 网页视频解析使用应用内WebView运行页面脚本，观察video、iframe关联网络、Fetch和XHR，验证候选媒体再交给原生播放器。最多两个解析实例，带超时与取消；不跳过证书错误，不绕过DRM或验证码。
- 网页线路支持手动选集、上下集和自动续集，每集重新解析短期媒体地址。HLS过滤与原时间线续播沿用0.2.0逻辑。

在“内容源→导入内容源”选择JSON，或勾选“保存为订阅”后填写规则链接。推荐先导入本次双源样本文件，实测范围与失败站点见release中的0.3.0验证报告。站点可随时变化，不把单次样本验证等同于整站长期稳定。

## 视频广告过滤（0.2.0起）

- 播放器默认开启HLS片段过滤，并显示实际判断结果；可在播放器中关闭。
- 导入Ficket列表时，带广告标记及已知三站（非凡影视、暴风、量子资源站）默认关闭。首次升级也会关闭此前导入的这些源；收藏与历史保留。用户可以自行重新启用。
- 对完整点播M3U8，识别成对广告起止标记、受约束的广告路径片段；已知广告源还可识别主内容之间有明显路径变化的短插入块。
- 不会仅凭短片段或DISCONTINUITY断点删除内容；“切片”分类不代表广告。
- 不处理画面内烧录的广告、普通MP4中的插入内容或无法区分的广告。直播、加密、分离音轨、fMP4与字节范围等情况保留原列表，并显示限制。解析失败会退回原列表。
- 过滤不是无广告保证。不能可靠识别时建议换源；不要把剩余27个源当作无广告认证。
- 续播进度按原视频时间线保存，开关过滤后仍能映射回相同位置。

## 明确的版本边界

- 这是可以继续开发的核心版，不是Ficket全部功能的完成版。
- 小说/漫画的CSS引擎仍解析静态HTML。视频新增WebView动态解析；复杂站点、验证码、DRM及网站专用播放器不能保证支持。
- MacCMS适配器支持JSON，不支持XML；其他接口需由已支持的Kazumi API规则进行映射。
- 需要网页播放器、登录或短时鉴权的地址可能不能在原生播放器播放，可尝试浏览器打开原地址。
- 支持后台播放、系统画中画、通知栏与耳机控制；投屏和离线下载管理暂未实现。后台播放和自动小窗可在播放器中分别关闭。
- 缓存是播放器流式磁盘缓存，不等同于可管理的离线下载任务。
- 从链接导入时可勾选保存订阅；启动检查和约每12小时的后台检查可能受系统省电策略延迟。支持单条JSON、源列表和Kazumi目录index.json。
- 尚未加入BT、云同步和公开源社区。
- 移除源会保留收藏，但再次打开时需要重新导入同一地址的规则。

## 构建

本机：Java 21、Gradle 9.2.0、Android SDK 36及Build Tools 36.0.0。项目使用AGP 9.0.1、内置Kotlin 2.2.10、Compose、Media3 1.9.0、OkHttp、Jsoup、Coil。

Windows可运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

或在Android Studio中打开项目。`local.properties`需要填写本机SDK路径；本文件不包含在源码分发包中。构建脚本仅为本次构建读取环境中的代理，不更改系统设置。

测试：

```powershell
.\gradlew.bat :app:testDebugUnitTest
.\gradlew.bat :app:connectedDebugAndroidTest
```

第一条验证接口请求、解析、多线路、规则导入、相对链接、正文清理、单源故障隔离和大小限制。第二条需要已启动的模拟器或已授权USB调试的手机，检查界面、SQLite持久化和原生播放器。
